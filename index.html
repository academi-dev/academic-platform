github.com/academi-dev/academic-api ↗

1. Login: de credenciales a un par de tokens

academic-api/app/auth/router.py · líneas 42–69
Ver en GitHub ↗

Este es el endpoint POST /api/v1/auth/login. Recibe correo y contraseña, delega la validación en authenticate_user y, si todo es correcto, emite dos tokens JWT:

  • access_token: vida corta (30 min por defecto). Se envía en cada petición.
  • refresh_token: vida larga (7 días). Solo sirve para pedir un nuevo access token.

El campo sub guarda el UUID del usuario; es lo que después usa la API para saber quién hace cada petición.

@router.post(
    "/login",
    response_model=TokenResponse,
    status_code=status.HTTP_200_OK,
    summary="Iniciar sesión",
    description="Valida credenciales y genera un par de tokens JWT (acceso y refresco)."
)
def iniciar_sesion(
    login_data: LoginRequest,
    db: Session = Depends(get_db)
) -> TokenResponse:
    """Autentica al usuario y devuelve el token de acceso y de refresco."""
    usuario = authenticate_user(db=db, email=login_data.email, password=login_data.password)
    
    token_data = {
        "sub": str(usuario.id),
        "email": usuario.email,
        "rol": usuario.rol.value
    }
    
    access_token = create_access_token(data=token_data)
    refresh_token = create_refresh_token(data=token_data)

    return TokenResponse(
        access_token=access_token,
        refresh_token=refresh_token,
        token_type="bearer"
    )

2. Cómo se firma un token

academic-api/app/auth/service.py · líneas 34–50
Ver en GitHub ↗

El token se firma con SECRET_KEY y el algoritmo HS256. Además de los datos del usuario se agregan exp (expiración), iat (emitido en) y type.

El campo type es una decisión de diseño: evita que alguien use un refresh token como si fuera un access token (se valida en el siguiente fragmento).

def create_access_token(data: Dict[str, Any], expires_delta: Optional[timedelta] = None) -> str:
    """
    Genera un token de acceso JWT firmado con expiración corta.
    """
    to_encode = data.copy()
    now_utc = datetime.now(timezone.utc)
    if expires_delta:
        expire = now_utc + expires_delta
    else:
        expire = now_utc + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRE_MINUTES)

    to_encode.update({
        "exp": expire,
        "iat": now_utc,
        "type": "access"
    })
    return jwt.encode(to_encode, settings.SECRET_KEY, algorithm=settings.ALGORITHM)

3. Validación del token (firma, vigencia y tipo)

academic-api/app/auth/service.py · líneas 72–105
Ver en GitHub ↗

verify_token decodifica el JWT y comprueba tres cosas: que la firma sea válida, que no haya expirado y que el type sea el esperado. Cada error se traduce a una respuesta 401 con un código legible (TOKEN_EXPIRADO, TOKEN_INVALIDO) en el formato estándar de errores de la API: {"error": {"codigo", "mensaje"}}.

def verify_token(token: str, expected_type: str = "access") -> Dict[str, Any]:
    """
    Decodifica y valida un token JWT comprobando firma, vigencia y tipo de token.
    Lanza APIError en caso de token inválido o expirado.
    """
    try:
        payload = jwt.decode(token, settings.SECRET_KEY, algorithms=[settings.ALGORITHM])
        token_type = payload.get("type")
        if token_type != expected_type:
            raise APIError(
                status_code=status.HTTP_401_UNAUTHORIZED,
                codigo="TOKEN_INVALIDO",
                mensaje=f"Tipo de token incorrecto. Se esperaba '{expected_type}'."
            )
        user_id = payload.get("sub")
        if not user_id:
            raise APIError(
                status_code=status.HTTP_401_UNAUTHORIZED,
                codigo="TOKEN_INVALIDO",
                mensaje="El token no contiene un identificador de usuario válido."
            )
        return payload
    except jwt.ExpiredSignatureError:
        raise APIError(
            status_code=status.HTTP_401_UNAUTHORIZED,
            codigo="TOKEN_EXPIRADO",
            mensaje="El token ha expirado. Por favor inicie sesión nuevamente."
        )
    except jwt.InvalidTokenError:
        raise APIError(
            status_code=status.HTTP_401_UNAUTHORIZED,
            codigo="TOKEN_INVALIDO",
            mensaje="El token proporcionado no es válido."
        )

4. Protección de rutas con inyección de dependencias

academic-api/app/auth/dependencies.py · líneas 21–71
Ver en GitHub ↗

get_current_user es una dependencia de FastAPI. Cualquier endpoint que declare Depends(get_current_user) queda protegido automáticamente: se lee el header Authorization: Bearer …, se valida el token y se carga el usuario desde la base de datos.

get_current_admin_user se apoya en la anterior y además exige el rol ADMIN (control de acceso basado en roles, RBAC).

def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db)
) -> User:
    """
    Dependencia que extrae y valida el JWT del encabezado Authorization.
    Verifica que el usuario exista en la base de datos y se encuentre activo.
    """
    payload = verify_token(token, expected_type="access")
    user_id_str = payload.get("sub")

    try:
        user_uuid = uuid.UUID(str(user_id_str))
    except (ValueError, TypeError):
        raise APIError(
            status_code=status.HTTP_401_UNAUTHORIZED,
            codigo="TOKEN_INVALIDO",
            mensaje="El identificador de usuario en el token tiene un formato inválido."
        )

    user = db.query(User).filter(User.id == user_uuid).first()
    if not user:
        raise APIError(
            status_code=status.HTTP_401_UNAUTHORIZED,
            codigo="NO_AUTORIZADO",
            mensaje="El usuario asociado al token no existe."
        )

    if not user.is_active:
        raise APIError(
            status_code=status.HTTP_403_FORBIDDEN,
            codigo="ACCESO_DENEGADO",
            mensaje="La cuenta de usuario se encuentra inactiva."
        )

    return user


def get_current_admin_user(
    current_user: User = Depends(get_current_user)
) -> User:
    """
    Dependencia que restringe el acceso exclusivamente a usuarios con rol ADMIN.
    """
    if current_user.rol != UserRole.ADMIN:
        raise APIError(
            status_code=status.HTTP_403_FORBIDDEN,
            codigo="ACCESO_DENEGADO",
            mensaje="Esta acción requiere privilegios de administrador."
        )
    return current_user

5. Registro seguro: el rol no lo decide el cliente

academic-api/app/auth/service.py · líneas 134–159
Ver en GitHub ↗

Al registrar se normaliza el correo, se verifica que no exista (409 si ya existe) y la contraseña se guarda con hash bcrypt, nunca en texto plano.

Fíjese en la línea con rol=UserRole.ESTUDIANTE: aunque alguien envíe "rol": "admin" en el JSON, el servidor lo ignora. La prueba de integración verifica justamente este caso.

def create_user(db: Session, user_data: RegistroRequest) -> User:
    """
    Registra un nuevo usuario en la base de datos previa verificación de unicidad de correo.
    """
    email_clean = user_data.email.lower().strip()
    existing_user = db.query(User).filter(User.email == email_clean).first()
    if existing_user:
        raise APIError(
            status_code=status.HTTP_409_CONFLICT,
            codigo="CORREO_REGISTRADO",
            mensaje="Ya existe una cuenta registrada con este correo electrónico."
        )

    new_user = User(
        id=uuid.uuid4(),
        email=email_clean,
        hashed_password=get_password_hash(user_data.password),
        nombre=user_data.nombre.strip(),
        rol=UserRole.ESTUDIANTE,
        is_active=True,
        created_at=datetime.now(timezone.utc)
    )
    db.add(new_user)
    db.commit()
    db.refresh(new_user)
    return new_user

6. Modelo de datos de una tarea

academic-api/app/tareas/models.py · líneas 29–60
Ver en GitHub ↗

Modelo SQLAlchemy de la tabla tareas. Puntos a notar:

  • Claves primarias UUID (no enteros consecutivos, así no se pueden adivinar IDs).
  • prioridad y estado son enums: la base de datos solo acepta valores válidos.
  • Dos llaves foráneas con ondelete="CASCADE": si se borra la materia o el usuario, se borran sus tareas.
  • usuario_id está indexado porque todas las consultas filtran por él.
class Tarea(Base):
    """
    Modelo SQLAlchemy de la entidad Tarea.
    Representa una actividad o entrega académica vinculada a una materia.
    """
    __tablename__ = "tareas"

    id = Column(GUID, primary_key=True, default=uuid.uuid4)
    titulo = Column(String(200), nullable=False)
    descripcion = Column(Text, nullable=True)
    fecha_entrega = Column(DateTime(timezone=True), nullable=True)
    prioridad = Column(
        Enum(TareaPrioridad, values_callable=lambda obj: [e.value for e in obj]),
        default=TareaPrioridad.MEDIA,
        nullable=False
    )
    estado = Column(
        Enum(TareaEstado, values_callable=lambda obj: [e.value for e in obj]),
        default=TareaEstado.PENDIENTE,
        nullable=False
    )
    materia_id = Column(GUID, ForeignKey("materias.id", ondelete="CASCADE"), nullable=False, index=True)
    usuario_id = Column(GUID, ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True)
    created_at = Column(
        DateTime(timezone=True),
        default=lambda: datetime.now(timezone.utc),
        nullable=False
    )

    # Relaciones
    usuario = relationship("User", back_populates="tareas")
    materia = relationship("Materia", back_populates="tareas")

7. Aislamiento entre usuarios y filtros

academic-api/app/tareas/service.py · líneas 17–64
Ver en GitHub ↗

Aquí está la regla de seguridad más importante del negocio: cada consulta empieza filtrando por usuario_id. Un estudiante nunca puede listar, ver ni borrar tareas de otro.

_validar_materia_propietario impide además crear una tarea dentro de una materia ajena. Los filtros opcionales (materia, estado, rango de fechas) se encadenan sobre la misma consulta y al final se aplica paginación con limite y desplazamiento.

def _validar_materia_propietario(db: Session, materia_id: uuid.UUID, usuario_id: uuid.UUID) -> Materia:
    """
    Valida que la materia exista y pertenezca al usuario solicitante.
    """
    materia = db.query(Materia).filter(
        Materia.id == materia_id,
        Materia.usuario_id == usuario_id
    ).first()
    if not materia:
        raise APIError(
            status_code=status.HTTP_404_NOT_FOUND,
            codigo="RECURSO_NO_ENCONTRADO",
            mensaje=f"La materia con ID '{materia_id}' no existe o no pertenece al usuario."
        )
    return materia


def get_tareas(
    db: Session,
    usuario_id: uuid.UUID,
    materia_id: Optional[uuid.UUID] = None,
    estado: Optional[TareaEstado] = None,
    fecha_inicio: Optional[datetime] = None,
    fecha_fin: Optional[datetime] = None,
    limite: int = 10,
    desplazamiento: int = 0
) -> Tuple[List[Tarea], int]:
    """
    Lista las tareas del usuario aplicando filtros opcionales de materia, estado y rango de fechas.
    Retorna una tupla (lista_tareas, total_registros).
    """
    query = db.query(Tarea).filter(Tarea.usuario_id == usuario_id)

    if materia_id is not None:
        query = query.filter(Tarea.materia_id == materia_id)

    if estado is not None:
        query = query.filter(Tarea.estado == estado)

    if fecha_inicio is not None:
        query = query.filter(Tarea.fecha_entrega >= fecha_inicio)

    if fecha_fin is not None:
        query = query.filter(Tarea.fecha_entrega <= fecha_fin)

    total = query.count()
    tareas = query.order_by(Tarea.fecha_entrega.asc(), Tarea.created_at.desc()).offset(desplazamiento).limit(limite).all()
    return tareas, total

1. Extraer el texto del PDF página por página

academic-rag/app/documentos/processor.py · líneas 69–92
Ver en GitHub ↗

Para poder citar la página exacta, el texto no se extrae como un bloque único: se recorre cada página con PyPDF2 y se guarda junto a su número (empezando en 1, como lo lee una persona). Si el PDF no tiene texto legible (por ejemplo, un escaneo sin OCR) se rechaza con un error claro.

        try:
            reader = PyPDF2.PdfReader(stream)
            total_pages = len(reader.pages)
            pages_data: List[Dict[str, Any]] = []

            for page_index in range(total_pages):
                page = reader.pages[page_index]
                text = page.extract_text() or ""
                clean_text = text.strip()

                if clean_text:
                    pages_data.append({
                        "pagina": page_index + 1,  # 1-indexado para citación humana
                        "texto": clean_text,
                    })

            if not pages_data:
                raise ValueError("El archivo PDF no contiene texto legible o está vacío.")

            return pages_data
        except Exception as e:
            if isinstance(e, ValueError):
                raise e
            raise ValueError(f"Error al analizar el archivo PDF: {str(e)}") from e

2. Fragmentación (chunking) con solapamiento

academic-rag/app/documentos/processor.py · líneas 97–133
Ver en GitHub ↗

Cada página se divide en fragmentos de máximo chunk_size caracteres (500). Entre fragmentos consecutivos se repiten chunk_overlap caracteres (50) para que una idea que queda partida entre dos fragmentos no se pierda.

Si LangChain está instalado se usa su RecursiveCharacterTextSplitter; si no, este algoritmo propio intenta cortar en un espacio o punto para no partir palabras.

    def _split_text_fallback(self, text: str) -> List[str]:
        """Algoritmo de respaldo para división de texto cuando LangChain no está disponible.

        Args:
            text: Cadena de texto a fragmentar.

        Returns:
            List[str]: Lista de fragmentos respetando chunk_size y chunk_overlap.
        """
        if len(text) <= self.chunk_size:
            return [text]

        chunks: List[str] = []
        start = 0
        text_len = len(text)

        while start < text_len:
            end = start + self.chunk_size
            chunk = text[start:end]

            # Intentar cortar por el último espacio o punto si no estamos al final
            if end < text_len:
                last_space = chunk.rfind(" ")
                last_period = chunk.rfind(". ")
                break_point = max(last_space, last_period)
                if break_point > int(self.chunk_size * 0.5):
                    chunk = chunk[: break_point + 1]
                    end = start + len(chunk)

            chunk_clean = chunk.strip()
            if chunk_clean:
                chunks.append(chunk_clean)

            step = len(chunk) - self.chunk_overlap
            start += max(1, step)

        return chunks

3. Cada fragmento conserva su página

academic-rag/app/documentos/processor.py · líneas 148–187
Ver en GitHub ↗

El resultado es una lista de fragmentos con pagina, posicion y texto. Estos metadatos viajan con el fragmento a la base vectorial y son los que permiten responder “esto está en la página 2 de apuntes.pdf”.

    def process_pages_to_chunks(
        self, pages_data: List[Dict[str, Any]]
    ) -> List[Dict[str, Any]]:
        """Transforma una lista de páginas en una lista de fragmentos con metadatos asociados.

        Args:
            pages_data: Lista de páginas obtenida con `extract_text_by_page`.

        Returns:
            List[Dict[str, Any]]: Fragmentos resultantes con la siguiente estructura:
                [
                    {
                        "pagina": int,
                        "posicion": int,
                        "texto": str
                    },
                    ...
                ]
        """
        chunks_result: List[Dict[str, Any]] = []
        global_position = 0

        for page_item in pages_data:
            page_number = page_item["pagina"]
            page_text = page_item["texto"]

            text_chunks = self.chunk_text(page_text)
            for chunk_content in text_chunks:
                clean_chunk = chunk_content.strip()
                if not clean_chunk:
                    continue

                chunks_result.append({
                    "pagina": page_number,
                    "posicion": global_position,
                    "texto": clean_chunk,
                })
                global_position += 1

        return chunks_result

4. Base vectorial: ChromaDB o respaldo local

academic-rag/app/vector_store.py · líneas 192–227
Ver en GitHub ↗

En Docker (Python 3.11) se usa ChromaDB con embeddings de sentence-transformers (modelo all-MiniLM-L6-v2). En el equipo de desarrollo (Python 3.15 en Windows) esas librerías no tienen versiones compiladas, así que se activa automáticamente LocalPersistentCollection, que tiene la misma interfaz (add, query, delete, count). El resto del código no sabe cuál de las dos está usando.

def create_vector_collection(settings: Settings) -> Any:
    """Inicializa y retorna una colección vectorial ChromaDB o el respaldo persistente local."""
    Path(settings.chroma_persist_dir).mkdir(parents=True, exist_ok=True)
    try:
        import chromadb  # type: ignore
        from chromadb.config import Settings as ChromaSettings  # type: ignore
        from chromadb.utils import embedding_functions  # type: ignore

        if not hasattr(chromadb, "PersistentClient"):
            raise RuntimeError("La versión instalada de chromadb no soporta PersistentClient.")

        client = chromadb.PersistentClient(
            path=settings.chroma_persist_dir,
            settings=ChromaSettings(anonymized_telemetry=False),
        )

        try:
            embedding_fn = embedding_functions.SentenceTransformerEmbeddingFunction(
                model_name=settings.embedding_model
            )
        except Exception:
            embedding_fn = embedding_functions.DefaultEmbeddingFunction()

        collection = client.get_or_create_collection(
            name=settings.collection_name,
            embedding_function=embedding_fn,
            metadata={"description": "Índice de fragmentos académicos"},
        )
        # Verificar que la colección sea operativa
        _ = collection.count()
        return collection
    except Exception:
        return LocalPersistentCollection(
            persist_dir=settings.chroma_persist_dir,
            collection_name=settings.collection_name,
        )

5. Cómo compara textos el respaldo local

academic-rag/app/vector_store.py · líneas 40–72
Ver en GitHub ↗

El respaldo convierte cada texto en un vector disperso: palabras sin tildes ni stopwords, más prefijos de 4 y 5 letras para captar variaciones (“complejidad” / “complejo”). Luego compara con similitud coseno.

Es una búsqueda léxica (por palabras), no semántica como la de ChromaDB con embeddings. Lo dejamos explícito en la sección de retroalimentación.

def _vectorize(text: str) -> Dict[str, float]:
    """Convierte un texto en un vector disperso L2-normalizado de palabras y n-gramas."""
    norm = _normalize_text(text)
    words = [w for w in re.findall(r"[a-z0-9]+", norm) if len(w) >= 2 and w not in _STOPWORDS_ES]
    counts: Counter[str] = Counter()
    for w in words:
        counts[f"w:{w}"] += 2.0
        if len(w) >= 4:
            # Prefijos/raíces para capturar variaciones morfológicas
            counts[f"p:{w[:4]}"] += 1.0
        if len(w) >= 5:
            counts[f"p:{w[:5]}"] += 1.0

    if not counts:
        # Fallback para textos muy cortos
        for token in re.findall(r"[a-z0-9]+", norm):
            counts[f"w:{token}"] += 1.0

    norm_sq = sum(v * v for v in counts.values())
    if norm_sq <= 0:
        return {}
    inv_norm = 1.0 / math.sqrt(norm_sq)
    return {k: v * inv_norm for k, v in counts.items()}


def _cosine_similarity(vec_a: Dict[str, float], vec_b: Dict[str, float]) -> float:
    """Calcula la similitud coseno entre dos vectores dispersos L2-normalizados."""
    if not vec_a or not vec_b:
        return 0.0
    if len(vec_a) > len(vec_b):
        vec_a, vec_b = vec_b, vec_a
    dot = sum(val * vec_b.get(key, 0.0) for key, val in vec_a.items())
    return max(0.0, min(1.0, dot))

6. Recuperar los fragmentos más relevantes

academic-rag/app/preguntas/service.py · líneas 32–96
Ver en GitHub ↗

Se consulta la colección con la pregunta y se piden los top_k fragmentos más cercanos (se puede filtrar por un documento específico). La distancia se convierte en un puntaje de relevancia entre 0 y 1, y cada resultado se empaqueta como una Cita con documento, página y texto.

    def retrieve_relevant_chunks(
        self, pregunta: str, top_k: int = 3, documento_id: Optional[str] = None
    ) -> List[Cita]:
        """Consulta ChromaDB para encontrar los fragmentos más afines a la pregunta.

        Args:
            pregunta: Consulta del usuario en lenguaje natural.
            top_k: Número de fragmentos a recuperar.
            documento_id: Filtro opcional por ID de documento específico.

        Returns:
            List[Cita]: Lista ordenada de citas con metadatos de documento y página.
        """
        count = self.collection.count()
        if count == 0:
            return []

        where_filter: Optional[Dict[str, Any]] = None
        if documento_id:
            where_filter = {"documento_id": documento_id}

        # Ajustar n_results si hay menos fragmentos indexados que top_k
        n_results = min(top_k, count)
        if n_results <= 0:
            return []

        try:
            results = self.collection.query(
                query_texts=[pregunta],
                n_results=n_results,
                where=where_filter,
                include=["documents", "metadatas", "distances"],
            )
        except Exception:
            return []

        citas: List[Cita] = []
        if not results or not results.get("documents") or not results["documents"][0]:
            return citas

        documents_list = results["documents"][0]
        metadatas_list = results.get("metadatas", [[]])[0]
        distances_list = results.get("distances", [[]])[0]

        for i, text in enumerate(documents_list):
            meta = metadatas_list[i] if i < len(metadatas_list) else {}
            dist = distances_list[i] if distances_list and i < len(distances_list) else None

            # Calcular score de relevancia normalizado a partir de distancia
            relevancia: Optional[float] = None
            if dist is not None:
                relevancia = round(max(0.0, 1.0 - float(dist)), 4)

            citas.append(
                Cita(
                    pagina=int(meta.get("pagina", 1)),
                    texto=text,
                    documento=str(meta.get("nombre_archivo", "apuntes.pdf")),
                    documento_id=meta.get("documento_id"),
                    posicion=meta.get("posicion"),
                    relevancia=relevancia,
                )
            )

        return citas

let pyProc = null;
let reqCounter = 0;
const pendingRequests = new Map();

function startPythonBridge() {
  const pythonBin = resolvePythonBin();
  pyProc = spawn(pythonBin, ["-m", "bot.whatsapp.bridge_cli"], {
    cwd: PROJECT_ROOT,
    env: { ...process.env, PYTHONIOENCODING: "utf-8" },
    stdio: ["pipe", "pipe", "inherit"],
  });

  let buffer = "";
  pyProc.stdout.on("data", (chunk) => {
    buffer += chunk.toString("utf-8");
    const lines = buffer.split("\n");
    buffer = lines.pop() || "";

    for (const line of lines) {
      if (!line.trim()) continue;
      try {
        const data = JSON.parse(line);
        const resolver = pendingRequests.get(data.id);
        if (resolver) {
          pendingRequests.delete(data.id);
          resolver(data);
        }
      } catch (err) {
        console.error("[Puente Python] Error parseando JSON:", err.message);
      }
    }
  });

  pyProc.on("exit", (code) => {
    console.warn(`[Puente Python] Proceso finalizado (${code}). Reiniciando en 2s...`);
    setTimeout(startPythonBridge, 2000);
  });
}

function askPythonProcessor(sender, text) {
  return new Promise((resolve) => {
    const id = String(++reqCounter);
    pendingRequests.set(id, resolve);
    const payload = JSON.stringify({ id, sender, text }) + "\n";
    pyProc.stdin.write(payload, "utf-8");
  });
}

async def main_loop() -> None:
    """Bucle principal de lectura por stdin y escritura por stdout en UTF-8."""
    if hasattr(sys.stdin, "reconfigure"):
        sys.stdin.reconfigure(encoding="utf-8")
    if hasattr(sys.stdout, "reconfigure"):
        sys.stdout.reconfigure(encoding="utf-8")

    loop = asyncio.get_running_loop()
    while True:
        line = await loop.run_in_executor(None, sys.stdin.readline)
        if not line:
            break
        line = line.strip()
        if not line:
            continue
        response = await _process_line(line)
        sys.stdout.write(json.dumps(response, ensure_ascii=False) + "\n")
        sys.stdout.flush()


if __name__ == "__main__":
    asyncio.run(main_loop())

El corazón del bot de WhatsApp. Funciona como una pequeña máquina de estados por usuario:

  • Si el usuario está a mitad de un flujo (por ejemplo, el login le pidió la contraseña), el mensaje continúa ese flujo.
  • Si no, se identifica el comando (/login, /materias, /preguntar…).

    async def handle_message(self, sender_id: str, raw_text: str) -> Dict[str, Any]:
        """Procesa un mensaje entrante de WhatsApp y retorna la respuesta y acciones opcionales.

        Args:
            sender_id: Identificador JID o número de WhatsApp (ej. '573001234567@s.whatsapp.net').
            raw_text: Texto enviado por el usuario.

        Returns:
            Diccionario con:
                - 'reply': Texto formateado para WhatsApp.
                - 'reminder': Diccionario opcional {'delay_seconds': int, 'text': str} si agendó recordatorio.
        """
        text = (raw_text or "").strip()
        if not text:
            return {"reply": self.get_welcome_menu(sender_id), "reminder": None}

        lower = text.lower()

        # Cancelación global de flujo guiado
        if lower in ("/cancelar", "/cancel", "cancelar"):
            if sender_id in self._states:
                self._states.pop(sender_id, None)
                return {"reply": "🚫 Operación cancelada. Escribe `/help` para ver los comandos.", "reminder": None}
            return {"reply": "ℹ️ No hay ninguna operación en curso.", "reminder": None}

        # Si el usuario está en medio de un flujo conversacional (login, registro, preguntar, recordar)
        if sender_id in self._states and not text.startswith("/"):
            return await self._continue_flow(sender_id, text)

        # Limpiar cualquier estado anterior si envía un nuevo comando explícito
        self._states.pop(sender_id, None)

        if lower in ("/start", "/help", "hola", "menu", "menú", "ayuda", "academic", "/academic"):
            return {"reply": self.get_welcome_menu(sender_id), "reminder": None}

        if lower.startswith("/logout") or lower == "salir":
            removed = self.storage.remove_token(sender_id)
            if removed:
                return {"reply": "👋 *Sesión cerrada correctamente.*\nUsa `/login` cuando desees volver a ingresar.", "reminder": None}
            return {"reply": "ℹ️ No tenías una sesión activa.", "reminder": None}

        if lower.startswith("/login"):
            return await self._handle_login_command(sender_id, text)

        if lower.startswith("/registro"):
            return await self._handle_register_command(sender_id, text)

        if lower.startswith("/materias") or lower == "materias":
            return {"reply": await self._handle_materias(sender_id), "reminder": None}

        if lower.startswith("/tareas") or lower == "tareas":
            return {"reply": await self._handle_tareas(sender_id, solo_pendientes=False), "reminder": None}

        if lower.startswith("/pendientes") or lower == "pendientes":
            return {"reply": await self._handle_tareas(sender_id, solo_pendientes=True), "reminder": None}

        if lower.startswith("/recordar"):
            return self._handle_recordar_command(sender_id, text)

        if lower.startswith("/preguntar"):
            return await self._handle_preguntar_command(sender_id, text)

        # Si el mensaje empieza con "/" pero el comando no existe, avisar al usuario.
        # Si es una conversación personal normal (sin "/"), ignorar para no interferir con chats personales.
        if text.startswith("/"):
            return {
                "reply": (
                    "🤔 No reconocí ese comando.\n"
                    "Escribe `/help` para ver la lista de comandos o usa `/preguntar <tu duda>` para consultar tus apuntes."
                ),
                "reminder": None,
            }
        return {"reply": "", "reminder": None}

    def _handle_response_errors(self, response: httpx.Response) -> None:
        """Verifica el código HTTP y lanza las excepciones de negocio correspondientes."""
        if response.is_success:
            return

        detail = self._extract_error_detail(response)
        code = response.status_code

        if code in (401, 403):
            raise ApiAuthError(detail)
        if code == 404:
            raise ApiNotFoundError(detail)
        if code == 409:
            raise ApiConflictError(detail)
        if code == 422:
            raise ApiValidationError(detail)
        if code >= 500:
            raise ApiClientError(f"Error interno del servidor académico: {detail}", code="ERROR_SERVIDOR", status_code=code)
        
        raise ApiClientError(detail, status_code=code)

2. Adjuntar el token a cada petición

academic-mobile/app/src/main/java/com/academic/mobile/data/api/AuthInterceptor.kt · líneas 11–38
Ver en GitHub ↗

Un interceptor de OkHttp agrega Authorization: Bearer <token> a todas las peticiones, excepto a login, registro y refresh. Así ninguna pantalla tiene que acordarse de enviar el token.

class AuthInterceptor(
    private val tokenManager: TokenManager
) : Interceptor {

    override fun intercept(chain: Interceptor.Chain): Response {
        val originalRequest = chain.request()
        val path = originalRequest.url.encodedPath

        // No adjuntar token en los endpoints públicos de autenticación
        if (path.endsWith("/auth/login") ||
            path.endsWith("/auth/registro") ||
            path.endsWith("/auth/refresh")
        ) {
            return chain.proceed(originalRequest)
        }

        val accessToken = tokenManager.getAccessToken()
        if (accessToken.isNullOrBlank()) {
            return chain.proceed(originalRequest)
        }

        val authenticatedRequest = originalRequest.newBuilder()
            .header("Authorization", "Bearer $accessToken")
            .build()

        return chain.proceed(authenticatedRequest)
    }

3. Renovar la sesión sin que el usuario lo note

academic-mobile/app/src/main/java/com/academic/mobile/data/api/TokenAuthenticator.kt · líneas 19–70
Ver en GitHub ↗

Cuando la API responde 401, OkHttp llama a este Authenticator. Este pide un nuevo par de tokens con el refresh token, los guarda y repite la petición original. Si falla dos veces o no hay refresh token, cierra la sesión. @Synchronized evita que varias peticiones simultáneas intenten renovar a la vez.

    @Synchronized
    override fun authenticate(route: Route?, response: Response): Request? {
        val path = response.request.url.encodedPath
        if (path.endsWith("/auth/login") ||
            path.endsWith("/auth/registro") ||
            path.endsWith("/auth/refresh")
        ) {
            return null
        }

        // Evitar bucles infinitos de reintento
        if (contarReintentos(response) >= 2) {
            tokenManager.clearSession()
            return null
        }

        val refreshToken = tokenManager.getRefreshToken()
        if (refreshToken.isNullOrBlank()) {
            tokenManager.clearSession()
            return null
        }

        return try {
            val refreshResponse = apiServiceProvider()
                .refrescarTokenSync(RefreshTokenRequest(refreshToken))
                .execute()

            val body = refreshResponse.body()
            if (refreshResponse.isSuccessful && body != null) {
                tokenManager.saveTokens(body.accessToken, body.refreshToken)
                response.request.newBuilder()
                    .header("Authorization", "Bearer ${body.accessToken}")
                    .build()
            } else {
                tokenManager.clearSession()
                null
            }
        } catch (_: Exception) {
            null
        }
    }

    private fun contarReintentos(response: Response): Int {
        var count = 1
        var prior = response.priorResponse
        while (prior != null) {
            count++
            prior = prior.priorResponse
        }
        return count
    }
}

4. MVVM: el ViewModel y el estado de la pantalla

academic-mobile/app/src/main/java/com/academic/mobile/ui/tareas/TareasViewModel.kt · líneas 43–127
Ver en GitHub ↗

La pantalla (Fragment) no llama a la API directamente. El ViewModel expone un StateFlow<UiState> (Idle, Loading, Success, Error) que la vista observa para mostrar el cargando, la lista o el error. Las llamadas corren en viewModelScope (corrutinas), así que no bloquean la interfaz y se cancelan solas si el usuario sale de la pantalla.

    /**
     * Carga la lista de tareas aplicando los filtros activos de materia y estado.
     */
    fun cargarTareas(
        materiaId: String? = filtroMateriaIdActual,
        estado: String? = filtroEstadoActual
    ) {
        filtroMateriaIdActual = materiaId
        filtroEstadoActual = estado
        _tareasState.value = UiState.Loading

        viewModelScope.launch {
            when (val result = tareasRepository.obtenerTareas(materiaId = materiaId, estado = estado)) {
                is Result.Success -> _tareasState.value = UiState.Success(result.data)
                is Result.Error -> _tareasState.value = UiState.Error(result.message)
            }
        }
    }

    /**
     * Carga las materias disponibles para poblar el selector al crear una tarea o mostrar el detalle.
     */
    fun cargarMateriasDisponibles() {
        viewModelScope.launch {
            val res = materiasRepository.obtenerMaterias()
            if (res is Result.Success) {
                _materiasDisponibles.value = res.data
            }
        }
    }

    /**
     * Obtiene el nombre legible de una materia a partir de su UUID si se encuentra en caché.
     */
    fun obtenerNombreMateria(materiaId: String): String? {
        return materiasRepository.obtenerMateriaEnCache(materiaId)?.let {
            "${it.codigo} · ${it.nombre}"
        }
    }

    /**
     * Carga el detalle de una tarea específica por su identificador UUID.
     */
    fun cargarDetalleTarea(tareaId: String) {
        _detalleTareaState.value = UiState.Loading
        viewModelScope.launch {
            if (_materiasDisponibles.value.isEmpty()) {
                val matResult = materiasRepository.obtenerMaterias()
                if (matResult is Result.Success) {
                    _materiasDisponibles.value = matResult.data
                }
            }
            when (val result = tareasRepository.obtenerTareaPorId(tareaId)) {
                is Result.Success -> _detalleTareaState.value = UiState.Success(result.data)
                is Result.Error -> _detalleTareaState.value = UiState.Error(result.message)
            }
        }
    }

                is Result.Error -> _operacionState.value = UiState.Error(result.message)
            }
        }

Flujos completos (cómo se conectan los proyectos)

📱 Un estudiante crea una tarea desde la app

  1. LoginActivity → POST /api/v1/auth/login → la API devuelve access + refresh token.
  2. TokenManager guarda ambos tokens cifrados.
  3. TareasViewModel.crearTarea() llama al repositorio en una corrutina.
  4. AuthInterceptor agrega Authorization: Bearer ….
  5. Nginx enruta /api/v1/tareas hacia academic-api.
  6. get_current_user valida el token y carga el usuario.
  7. create_tarea verifica que la materia sea suya y guarda en PostgreSQL → 201.
  8. Si el token expiró, la API responde 401 y TokenAuthenticator lo renueva y repite la petición.

🟢 Un estudiante pregunta por WhatsApp

  1. Escribe /preguntar ¿Qué complejidad tiene la búsqueda binaria?
  2. index.js recibe el mensaje y lo envía como JSON al proceso Python.
  3. bridge_cli.py lo pasa a WhatsAppCommandProcessor.handle_message.
  4. El procesador identifica /preguntar y llama a rag_client.ask_question.
  5. academic-rag busca los fragmentos más parecidos (retrieve_relevant_chunks).
  6. Arma la respuesta con documento y página (responder).
  7. El bot la formatea (format_rag_response) y Node.js la envía al chat.

⭐ Dónde pedimos su retroalimentación

Decisiones que tomamos conscientemente y en las que su criterio nos ayudaría a mejorar.

  1. Sesiones del bot en memoria

    El bot guarda el token de cada chat en un diccionario en memoria (bot/utils/auth_storage.py). Si el proceso se reinicia, todos deben volver a iniciar sesión. ¿Recomienda persistirlo (Redis o base de datos) y cifrarlo?

  2. El servicio RAG no valida el JWT

    Hoy cualquier cliente que llegue a academic-rag puede subir documentos y preguntar, y los documentos son compartidos entre usuarios. ¿Conviene validar el mismo JWT de la API y separar los documentos por usuario_id?

  3. Respuesta del RAG: extractiva vs. generada

    Sin una API key de OpenAI, la respuesta muestra los fragmentos encontrados con sus citas, pero no redacta un resumen. ¿Sería válido integrar un modelo local (por ejemplo, con Ollama) para generar la respuesta sin costo?

  4. Búsqueda léxica en el entorno local

    En Python 3.15 se usa el respaldo LocalPersistentCollection, que busca por palabras y recalcula los vectores en cada consulta (O(n)). En Docker se usa ChromaDB con embeddings reales. ¿Es aceptable esta estrategia o deberíamos fijar Python 3.11 en todos los entornos?

  5. Refresh tokens sin revocación

    Al cerrar sesión, el refresh token sigue siendo válido hasta que expira (7 días). ¿Recomienda una lista de revocación o rotación con detección de reutilización?

  6. WhatsApp con librería no oficial

    Baileys funciona como WhatsApp Web, lo que es práctico para el proyecto, pero no es la API oficial. Para un despliegue real, ¿migramos a la WhatsApp Cloud API de Meta?

  7. Respaldo sin cifrado en Android

    Si el dispositivo no soporta EncryptedSharedPreferences, TokenManager usa preferencias normales sin cifrar. ¿Es preferible bloquear el login en ese caso?

  8. Pendientes de validación

    La app Android está escrita completa pero aún no la hemos compilado ni probado en un dispositivo. El docker-compose.yml tampoco se ha ejecutado completo, porque no tenemos Docker instalado. Las pruebas actuales corren en modo local con SQLite. ¿Qué evidencia de despliegue esperaría ver?
